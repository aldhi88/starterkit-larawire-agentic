# Architecture and Sources of Truth

## Layers

1. **Code-first registry:** `config/apps/<app-key>.php` owns App name/modules/menus/icons/landing; `routes/apps/<app-key>.php` owns web routes; `.api.php` owns shared-gateway APIs. `StarterAppRegistry` discovers valid config+web-route pairs.
2. **Database projection:** `starter_apps`, `starter_app_mods`, `starter_app_routes`, and `starter_app_menus` are generated by `starter:sync`.
3. **Authorization:** role-module and role-landing pivots; `starter.authorize` checks App routes.
4. **Presentation:** full-page Livewire in `app/Livewire/Apps/<App>/<Module>/`, Blade in `resources/views/apps/<app-key>/<module>/`, curated licensed vendor references in `docs/template/<theme>/`, starter runtime views in `resources/themes/<theme>/views/starter/`, minimum runtime assets in `public/themes/<theme>/assets/`, and PowerGrid tables with active-theme adapter. Optional themes are separate Composer packages registered through `StarterThemeRegistry`. PHP data/actions may be shared, but rendered component hierarchy and styling remain independently owned by each theme; one theme is never the presentation base for another.
5. **Domain/data:** model persistence, service business flow/transactions/cross-model work, typed minimal repository interface, and repository reusable query/persistence.
6. **Cross-cutting:** `AuditLogService`, `StarterConfigService`, and `StarterContextService`.

## Business feature boundary

```text
Livewire/Controller → Service → Repository Interface → Repository → Model/Database
```

- Livewire/controllers handle transport input, request-shape validation, initial authorization, use-case invocation, and response; no query or business flow in views/components.
- Services own business rules, data-dependent authorization, transactions, multi-repository orchestration, audit grouping, and side effects—not SQL, manual pagination, or UI.
- Interfaces are minimal typed business contracts. Repositories own reusable query/filter/sort/aggregate/database pagination/eager loading/locking/bulk persistence and never read request/auth/session or produce UI. Models own table/casts/relations/small invariants.
- Persistent business modules use a domain interface/repository. A service is required for mutation, rule, transaction, audit, data authorization, side effect, or multi-operation coordination; simple read-only consumers may call an interface directly.
- No base/generic repository, magic filter, unrestricted `all()`, generic `query()`/`execute()` wrapper, or `Builder` contract unless tested composition is the real domain contract. Prefer models, bounded collections, paginator, scalar aggregates, or typed DTO/read models.
- Use constructor injection and central interface bindings. Keep schema/query changes inside repositories while contracts remain valid. Apply `performance.md` in repositories; test repository query/pagination/scope/budgets and service rule/transaction/auth/audit/rollback behavior.

## Starter and host isolation

- The starter is the `aldhi88/starterkit-larawire-agentic` Composer dependency. Project features treat `vendor/aldhi88/starterkit-larawire-agentic` as read-only. Universal improvements are implemented, tested, versioned, and released from the canonical package repository; the Laravel host updates its Composer lock.
- Composer discovery registers only the safe installer provider before installation. The installer requires supported fresh Laravel source, confirms APP_URL and database identity, then connects `StarterServiceProvider`, `StarterBootstrap`, environment, AGENTS instructions, and internal asset publication. Non-fresh source always stops before mutation. See root `README.md` for installation.
- Starter PHP lives under `Starter` namespace/layer. `StarterServiceProvider` owns core bindings, Livewire aliases, listeners, migration loader, view path, and persistent middleware; keep host `AppServiceProvider` for host bindings. Provide additional App aliases through `StarterBootstrap::configureMiddleware()` arguments—do not call `Middleware::alias()` afterward and erase `starter.*` aliases.
- Core migrations/routes/assets stay in the starter; host App migrations/features/tests/landing stay in host paths. Standard framework files remain in their Laravel locations.
- Root landing belongs in `app/Livewire/Landing` and `resources/views/landing`; it is not a starter feature. Project UI extensions use only documented `resources/views/extensions/starter/` contracts and never override core view/layout.
- The installer owns only its marked host `AGENTS.md` connector block; preserve surrounding project instructions.

## App structure and routes

- Place App business features only under `Apps/<Subdomain>` in used layers. PHP namespace/path uses PascalCase (for example `Sales`); routes/config/views/translations/assets use lowercase (`sales`). Create only needed folders.

```text
app/{Livewire,Http/Controllers,Services,Contracts,Repositories,Rules}/Apps/<Subdomain>/<Module>/
app/{Models,Support}/Apps/<Subdomain>/
resources/views/apps/<subdomain>/<module>/{assets/}
public/assets/apps/<subdomain>/vendor/
lang/id/apps/<subdomain>/
tests/Feature/Apps/<Subdomain>/
database/migrations/apps/<subdomain>/
```

- Optional middleware, policies, jobs, events, listeners, notifications, and commands follow the same App ownership. Direct config/routes files remain at `config/apps/<subdomain>.php` and `routes/apps/<subdomain>.(api.)php` for discovery.
- Starter global routes serve profile/settings/logs/lock/session on all domains; starter web routes serve root auth; host `routes/web.php` serves root landing/project routes. `StarterRouteRegistrar` mounts App web routes at `<app>.<APP_DOMAIN>` and enabled API routes at `api.<APP_DOMAIN>/<app>` named `api.<app>.*`; `<app>.anchor` is the initial redirect exception.
- App route names are `<app>.<module>.<action>`. `api.<APP_DOMAIN>` is infrastructure, not an App; Scramble serves docs/OpenAPI there.

Prove ownership/source of truth before editing. Change App metadata in source then sync—never directly in the database. Avoid duplicate ownership across config/database/public state and avoid preference-only helpers/events/abstractions.
